# 过程模型与数据说明

## 模型要点

`backend/simulator/model.py` 是一个简化的污水厂过程模型，目标是让数据经得起懂行的人看：

| 现象 | 建模方式 |
| --- | --- |
| 进水量 | 日内双峰（北京时间 8:30、20:00），降雨时入流入渗抬高水量并稀释浓度 |
| 初期冲刷 | 旱天管道积泥，降雨初期被冲刷，进水浓度短时升高 |
| 溶解氧 | 氧平衡 `dDO/dt = KLa(风量)·(DOsat − DO) − OUR`，PI 控制风量（带抗积分饱和） |
| 硝化 | 受 DO（Monod）、水力停留时间、污泥浓度、水温共同影响，出水氨氮一阶滞后 |
| 污泥流失 | 流量超过设计值 1.3 倍时 MLSS 下降，约 12 小时恢复 |
| 反硝化 / 除磷 | 碳源、PAC 投加均为前馈 + PI 控制；渗漏、堵塞时表现为药耗异常或总磷超标 |

标定结果（`tests/test_simulator.py`）：正常工况出水全部达到一级 A 标准，吨水曝气电耗约 0.10 kWh；暴雨后 P03 氨氮超标并在一天内恢复；鼓风机振动超过 7.1 mm/s 后才跳停。

## 数据说明

| 表 / 视图 | 内容 |
| --- | --- |
| `plant` / `device` | 7 座厂站、57 台设备台账 |
| `plant_reading` | 厂站运行数据：进出水水质、DO、风量、电耗、药耗（hypertable，回填 1 分钟、实时 5 秒） |
| `plant_reading_1h` | 小时均值连续聚合，Text2SQL 首选 |
| `device_reading` | 设备电流、振动、温度（回填每分钟、实时每 30 秒） |
| `weather` | 降雨、气温 |
| `alarm` | 告警事件：规则、开始/恢复时间、峰值、触发参数（`detail`）、处理状态、处置建议（`advice`） |
| `work_order` | 工单：来源告警、负责人、步骤（含 AI 建议的引用）、状态、开始/关闭时间、处理结果 |
| `report` | 日报/周报：Markdown、统计事实（`facts`）、生成信息（`meta`：叙述来源、模型、校验记录） |
| `vision_inspection` | 视觉巡检记录：摄像头、图片 sha256、模型、检测框、耗时、关联告警；视觉告警复用 `alarm` 表（`kind = 视觉巡检`） |

回填数据内置 4 个历史事件，时间相对回填结束时刻：
- 5 天前：全区降雨；
- 3.5 天前：P05 碳源管道渗漏 18 小时；
- 2 天前：P02 加药泵堵塞 4 小时，出水总磷超标；
- 1 天前：P06 鼓风机故障，跳停约 90 分钟；本次回填数据中，出水氨氮按 5 分钟均值累计超标约 2.5 小时。

另有随机小雨。

Redis 键与频道：

| 名称 | 类型 | 内容 |
| --- | --- | --- |
| `sim:clock` | 键 | 演示时钟当前时间（北京时间 ISO 格式）。**下游一律以它为「现在」**，因为加速后它会领先墙上时间 |
| `realtime:latest` | 键 | 最新一帧完整数据（JSON） |
| `realtime:tick` | 频道 | 每步推送一帧 |
| `sim:control` / `sim:events` | 频道 | 控制命令 / 命令执行结果 |
| `alarm:events` | 频道 | 告警变化：`new` / `escalated` / `recovered`；启动补扫只发一条 `backfill` 汇总。`/ws/realtime` 原样转发（`type: "alarm"`） |
| `alarm:scan:lock` / `alarm:advice:lock:{id}` | 键 | 巡检锁（多实例只有一个在扫）/ 同一告警的处置建议生成锁 |
| `wo:draft:{id}` | 键 | 工单草稿，30 分钟过期，确认时一次性取出 |

Text2SQL 使用只读账号 `text2sql_ro`：只能读 `plant`、`plant_reading`、`plant_reading_1h`、`device`、`device_reading`、`weather` 这 6 张表，语句超时 5 秒。
