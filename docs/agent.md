# AI：Agent 连续对话

Agent 使用 **LangGraph + DeepSeek Flash**，以经过严格校验的 JSON 协议选择工具：规划 → 执行只读工具 → 根据结果补查或综合回答。现有网关不需要原生 `tool_calls` 参数；模型只能选择 `sql_query(question)`、`rag_search(question)` 与 `plant_statistics(parameters)`，不能直接传入 SQL、执行代码或写设备。查数仍经过 Text2SQL 的 SQL 防护与只读账号，检索复用混合检索和 Flash 重排；统计使用参数化固定 SQL 和同一只读账号，不让模型计算异常时长或排名。

```bash
curl -s localhost:8000/api/ai/chat \
  -H 'Content-Type: application/json' \
  -d '{"question":"黄官镇昨天是否氨氮超标？结合DO和鼓风机状态分析可能原因。"}'

# 将上一次响应的 session_id 填入，继续追问
curl -s localhost:8000/api/ai/chat \
  -H 'Content-Type: application/json' \
  -d '{"question":"那它今天最新的氨氮和DO是多少？","session_id":"上次响应的32位会话id"}'

curl -N localhost:8000/api/ai/chat/stream \
  -H 'Content-Type: application/json' \
  -d '{"question":"黄官镇昨天为什么氨氮升高？"}'
```

响应含 `session_id`、`run_id`、本轮 `now`、补全指代后的 `resolved_question`、`intent`、`answer`、`claims`、`citations`、`tool_calls`、实际 `models`、token 与耗时。所有子查询使用同一个演示时钟解释相对时间。历史只提供语境，旧查询结果不能充当本轮新证据。

三类引用分别核验：数据引用必须指向本轮成功查询的实际行、列和单元格值；知识引用必须指向本轮检索出的片段且摘录存在于原文中；统计引用必须选择本轮 `plant_statistics` 返回的真实事实 ID，整句、单位、聚合口径、时间范围及覆盖由服务端提供。`tool_calls` 保留实际 SQL、完整结果表、检索片段、调用参数、状态、执行耗时与排队耗时；模型上下文最多读取每次查数的前 30 行，截断会明确提示。原因假设必须同时附数据与知识引用，并显示“待核查”；核查建议必须有知识出处。固定统计之外的普通文本仍只核对引用，不保证任意自然语言推导或因果关系正确。

每轮最多 2 次规划、5 次工具调用，每批最多 3 个。相互独立的同批工具并行执行，同一 Agent 实例的多个会话共用默认 3 个并发额度；先按规划顺序分配稳定 ID，再执行工具，完成顺序不会改变引用。超时和连接取消会收集并取消子任务、释放额度。规划格式和最终引用各允许一次修复；普通工具按问题去重，固定统计按规范化参数去重。补查阶段固定沿用首轮补全的问题和意图；补查规划连续两次不合格时，按已获得的证据作答并给出警告。首轮规划沿用 Flash 默认思考，第二轮规划及其修复、综合回答关闭思考（`thinking.type=disabled`）；首轮规划因推理过长在 token 上限截断时，修复也关闭思考；预算均为 4000 token。提示词要求回答不超过 5 条陈述，每条不超过 6 个单元格引用和 2 段知识摘录；校验硬上限分别放宽到 6、12、3，模型多写几项时不必整轮重写，每个引用仍逐项核对；按硬上限估算最坏约 3800 token，仍在预算内。规划 `action` 为 tools/answer 时 `reason` 超过 400 字直接截断（不展示、不承载事实），拒答理由超长仍走修复。省略的引用列表按空列表处理，各类陈述需要的引用照常校验。校验失败时用中文反馈具体字段和上限，例如“claims: 最多6项，当前7项，请合并或删减”。可答时模型填写的 `reason` 没有出处，不展示。模型上下文中的行列显式标注编号，减少引用索引错误；`generation_calls` 保存规划与综合调用的 token、耗时和 `finish_reason`，可区分 token 截断与一般格式错误。工具最多运行 60 秒，整轮最多 180 秒。查数失败、空结果和能力拒答分别保留状态，不把失败计成成功，也不把空表解释为零。模型输出通过证据校验后才成为回答。

计时分开保留：网关 `latency_ms` 是最终成功的单次请求，`total_latency_ms` 包含失败尝试、实际退避与厂商切换；`attempt_history` 逐次保存状态、厂商、HTTP 状态码、耗时和退避。最终失败也进入总耗时统计，缓存命中为零；旧录制缺少总耗时时保留 `null`，上层回退到旧耗时，不冒充完整计时。`generation_calls` 保存规划/回答及子工具生成记录。业务 `llm_ms` 是各模型调用耗时之和，并行时可能大于整轮墙钟 `total_ms`；判断用户等待时间应看后者。网关分位数分别报告逻辑请求总耗时、所有实际尝试、成功单次请求；保留最近 500 次，缓存/回放不重复计入实时分位数。token 仅统计收到的 usage，不能据此断言失败请求不计费。

会话存于 Redis，保留最近 6 轮完整结果，完成一轮后续期 24 小时。同一会话并发请求返回 409，过期/未知会话返回 404；不带 `session_id` 即新建。会话锁使用带令牌的 240 秒租约，避免断开或旧请求覆盖新结果。对话接口需要管理员登录。会话 id 只用来区分不同对话；系统只有一个账号，不做多用户或租户隔离。

**对话内派单入口。** 每轮结束后，服务端在响应里附 `actions`（最多 3 条），模型不参与：范围只取本轮已确定的信息——`plant_statistics` 的厂站（不超过 3 个）与时段、补全后问题里写明的厂站和起止时间（都没有时取最近 24 小时），再查这些厂站在该时段前后 1 小时内未关闭的告警，补全后问题里问到的指标排最前，其次是工具子问题里查到的指标，再按级别和时间。全区排名等涉及 4 个以上厂站的问题不给入口。用户显式写出告警编号（`#25`、`告警25`、`告警编号 25`）时，即使 Agent 按能力边界拒答也会给出该告警。按范围匹配不要求回答成功：查数超时、证据不足而拒答时，问到的厂站时段里的告警仍会列出；只有能力边界外的问题不按范围匹配。每条入口带已有未关闭工单的编号。前端点“生成工单草稿”后走原有草稿与确认接口，生成草稿和提交时都带上该轮 `session_id/run_id`。只有该轮问的正是这条告警，草稿步骤才取这一轮回答的核查建议：用户显式点名了它，或补全后的问题问到它的指标（设备告警则问到设备）；工具子问题里顺带查到的指标不算。另外要求回答成功、确有核查建议。这些步骤保留知识、单元格和统计引用，来源记为 `chat_answer`。否则依次退回告警已保存的处置建议、模板；会话过期也照常出草稿。确认派单时，只有该轮确实给过这条告警的入口才写回会话（`followups`），下一轮规划的 history 会看到“用户已人工确认派单：工单 #N（告警 #A，负责人 X）”。Agent 本身仍只有三个只读工具，派单只能由人确认。

SSE 事件为 `run_start`、`planning`、`tool_start`、`tool_end`、`answer_start`、`done`；每 15 秒有保活注释，传输/保存异常返回 `error`。`done` 携带与 JSON 接口一致的完整响应，其中仍需检查 `ok/refused/error`。这些是任务与工具执行进度，回答在引用校验后一次返回，不是模型逐 token 输出，也不展示内部推理。连接断开会取消未完成任务并释放会话锁；已保存的结果可通过会话接口查看，当前不提供 SSE 事件重放。

## 固定统计与统计陈述

`POST /api/ai/statistics` 不依赖模型配置，也供 Agent 的第三个只读工具使用。参数为 `plant`（P01–P07 或 null）、指标目录中的 `metric`、明确的 `start/end`、`statistics`，以及可选 `rank_by`；单次不超过 31 天。示例：

```bash
curl -s localhost:8000/api/ai/statistics \
  -H 'Content-Type: application/json' \
  -d '{"plant":"P06","metric":"nh3n_out","start":"2026-11-06T00:00:00+08:00","end":"2026-11-07T00:00:00+08:00","statistics":["exceed_hours","longest_exceed_hours","instant_max","bucket_mean_max","hours_with_exceed"]}'
```

- 累计时长统计异常的 5 分钟均值桶数；最长连续时长统计相邻异常桶的最长一段。**缺失桶打断统计连续性**，与告警规则中“缺失不打断确认计数”的目的不同；无数据不返回零值事实。
- 原始采样极值 `instant_max/min` 与 5 分钟均值极值 `bucket_mean_max/min` 分别计算。`hours_with_exceed` 只数小时桶内是否曾有超标原始采样，不能当成连续时长。
- 起点向上、终点向下对齐 5 分钟，终点不超过演示时钟，只纳入已写满的桶；返回请求和实际统计范围。每桶至少一个有效采样才算有效桶，覆盖完整也不代表桶内持续观测。
- `mean` 对有效的 5 分钟桶等权平均，避免不同桶采样密度改变时段均值；无异常阈值的指标不能求超标时长。阈值判断使用未四舍五入的桶均值。
- 排名按 `rank_by=mean/instant_max/bucket_mean_max/exceed_hours` 的显示值（四位小数）降序，保留并列，采用密集排名。比较对象至少两座且所有厂站覆盖完整，才生成 `rank/range/top`；否则给缺口提示。
- `kind=statistic` 只能带真实 `statistic_refs`，模型正文必须为空；服务端生成整句并附单位、聚合方式、覆盖和时间；同一条陈述合并多条事实时，相同的覆盖说明（“有效 N/N 个 5 分钟桶”）只在句末写一次，每条引用里仍保留完整文本（事实的 `note` 字段）。普通单元格引用中的已知时长/峰值/排名句式会被拒绝，但这仍不是任意中文的通用语义验证器。当前固定统计覆盖厂站指标，设备极值尚无对应固定统计事实。

模拟历史的 2026-11-06 黄官镇结果：5 分钟均值累计与最长连续超标均为 **2.5 小时 / 30 桶**，曾有原始采样超标的小时桶为 **4 个**；原始采样最大值 **17.3209 mg/L**，5 分钟均值最大值 **16.7281 mg/L**，全天覆盖 **288/288 桶**。

```bash

uv run python -m evals.agent.performance --label my-comparison --repeats 2
```
