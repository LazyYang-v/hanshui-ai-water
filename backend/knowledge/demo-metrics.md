# 汉水智控 Demo 的数据口径与能力边界

## 出水指标和模拟阈值 {#effluent-limits}

本 Demo 用出水 COD、氨氮 NH3-N、总氮 TN、总磷 TP 和悬浮物 SS 观察水质，单位均为 mg/L。指标目录采用固定上限：COD 50、氨氮 5、总氮 15、总磷 0.5、SS 10。氨氮是总氮的一部分，二者不能互换；PAC 主要用于化学除磷，外加碳源主要支持反硝化脱氮。固定模拟阈值不会自动根据水温、季节或排放许可证变化，不能由此推导实际厂站的排放合规结论。项目没有对官方标准全文进行版本核验，实际判断需要相应标准、许可证和经核验的监测数据。

## 演示时钟与采样频率 {#clock-sampling}

系统的“现在”优先取 Redis 中的 sim:clock，即演示时钟；加速模拟后它可能领先电脑时间。历史回填默认每分钟一个样本，实时厂站数据通常每 5 秒一个样本，实时设备数据每 30 秒记录一次。设备运行时长不能在混合采样数据中直接用行数当分钟数。独立 Text2SQL 评测库使用固定的一分钟采样，所以明确注明每分钟一条的评测题可按样本数计算运行分钟。生产接口的统计按时间桶处理；所有自然日和事件时间以北京时间解释。

## 小时均值与累计量的区别 {#hourly-aggregation}

plant_reading_1h 存储小时均值。进水流量 inflow_m3h 的单位为立方米每小时，鼓风机功率 blower_kw 为千瓦，碳源和 PAC 投加速率为 kg/h。完整小时的平均速率乘一小时，才得到该小时的水量、电量或药量；不能直接把原始瞬时值相加当作累计量。未满小时、缺测和混合采样需要按实际持续时间加权。当前 Text2SQL 的累计量以小时均值求和估算，适合 Demo 分析。小时表还保存氨氮和总磷的小时最大值，判断某小时是否发生过超标时，应使用相应最大值，不能只看平均值。

## 进水污染负荷预警 {#influent-load}

COD、总氮和氨氮的质量负荷按同一采样的流量（m³/h）×浓度（mg/L）÷1000计算为kg/h，然后取5分钟均值；流量均值乘浓度均值在两者相关时会产生不同结果。派生指标分别为 cod_load_kgh、tn_load_kgh、nh3n_load_kgh，原始 cod_in、tn_in、nh3n_in 仍为mg/L。inflow_load告警中的触发值、阈值和峰值均为kg/h。

判断桶使用其所在整点以前7天同一北京时间钟点的完整小时历史，至少3个小时样本。默认质量负荷需同时超过历史中位数的1.5倍及中位数加3倍稳健标准差，浓度需同时超过中位数的1.25倍及同一稳健界限；稳健标准差为1.4826×MAD。连续3个有效异常桶确认，3个有效正常桶恢复，缺失不计数也不中断。这是Demo运行关注阈值，不是进水或出水排放标准。质量负荷与浓度同时升高提示核查进水来源和仪表；仅雨天水量增加、浓度稀释不直接判作浓度型污染冲击，实际雨天也可能伴随初期冲刷，应结合流量、浓度、雨量及出水、DO变化核查。不能仅凭告警断定上游偷排或已造成出水超标。

进水基线及药耗模型也按每个历史判断时刻的整点取此前完整小时，不以当前扫描结束时的模型反推全部历史。过去异常仍可能进入历史，由中位数、MAD或稳健拟合降低影响，不依据模拟场景标签删样本。

## 知识问答与查数的区别 {#capabilities}

RAG 知识问答提供工艺解释、排查思路和有出处的文档摘要，不读取实时测点，也不执行设备控制。询问某厂今天氨氮多少、昨天处理多少水、某台风机何时跳停，应通过 Text2SQL 或业务 API 查数。原因诊断需要将时间序列证据与知识结合，并列出还缺少的现场核查信息，不能单靠知识文档断言某次异常的原因。Demo 所有运行数据由模拟器生成；参考案例 PDF 的节电和药耗收益属于外部案例报道，不能作为本项目实测成绩。知识库也不包含员工联系方式、电价合同或未来天气预报。
